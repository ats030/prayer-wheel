# Design — Shiseki Map

`shiseki-map` は `onsen-map` の Go / Leaflet / SQLite / Wikipedia / Cloud Run 構成を
流用する姉妹アプリです。共通する視覚規約の正本は
[`omatsuri-map`](../omatsuri-map/DESIGN.md) とし、生成り・藍・朱の役割、Workbench
レイアウト、4px基準の余白、短い状態遷移を維持します。

## Domain-specific structure

- 検索: 名称・地域、都道府県、カテゴリ、時代、指定区分。各欄はパネル幅いっぱいに1行ずつ並べます。カテゴリ・時代・指定区分はチェックボックス群の折りたたみ(`details.multi-select`)で複数選択します。未選択は「すべて」、各項目内は OR で絞り込み(複数カテゴリの史跡はいずれかが一致すれば表示)。時代の選択肢は「・」で区切られた複合値を個別の時代に分け、旧石器時代から令和時代までの「◯◯時代」へ寄せて時系列に並べます(細分や幕末・戦国時代は親の時代へ、地質時代の更新世は分類しない)。いずれかが一致すれば表示し、詳細には元の表記を表示します、項目間は AND で組み合わせ、見出しには「すべて」・単一ラベル・「X ほかN」を表示します。
- 指定区分: 特別史跡、国指定、地方指定、未指定・不明。法的指定と一般的な歴史スポットを混同しない。
- マーカー: カテゴリを色で示し、同じ情報を凡例と詳細の文字でも示す。複数カテゴリは先頭の色、欠損・未知は「その他」の色を使う。凡例は全10カテゴリを2列で表示する。指定区分は検索と詳細に残す。近いマーカーはズームに応じて件数付きのクラスタ(墨色の円)にまとめ、クリックで拡大する。同じ座標の史跡は最大ズームでクラスタをクリックすると放射状に展開し、座標そのものは変えない。選択中の史跡はクラスタ外に強調マーカーで重ねて表示する。
- 詳細: 概要、写真、歴史、遺構・見どころ、アクセス、指定情報、出典、宿泊導線。
- 欠損値: 掲載対象から除外せず「未登録」または「情報なし」と表示する。

## Data and provenance

- 表示データは `scripts/fetch_shiseki.py` で生成する静的スナップショット。
  個別照合済みの自治体データは `data/verified_public_sites.json` から追加し、
  Wikidata QIDとは別の出典別 `id` を使う。再生成時も確認済みの15件を合成する。
  名前の違う既存点と同一の遺跡は `same_site_qid` で統合し、50m未満に近接する別物件は
  `distinct_from_qids` に照合済みのQIDを書いた場合だけ別マーカーにする。
- 自治体データには提供元・ライセンス・現行の訪問案内を別フィールドで保持し、
  詳細にリンクと加工表示を出す。古いCSVの公開曜日・時間は掲載しない。
- 国指定・特別史跡は文化庁の指定区分を正本とし、Wikidataを座標・名称・記事対応に使う。
- 文化庁 国指定文化財等データベースの史跡・特別史跡CSVを `scripts/bunka_shiseki.py` で取り込む
  (CSVは `data/bunka_cache/` に取得日とともに保存し、git管理外)。既存行との照合は
  ① Wikidata P4275(管理対象ID) ② 同一都道府県の正規化名一致 ③ 同一都道府県で名称の包含かつ1km以内の最近傍
  ④ 50m未満かつ固有部分の名称が共通する行、の順に行う。古墳群・遺跡群と構成要素の1基、
  墓所・窯跡などと近くの社寺は統合しない。照合できた行は文化庁の区分と詳細ページを指定の根拠にし、
  照合できず座標のある史跡は `bunka:401:<管理対象ID>`(P4275のQIDがあればQID)で新規行にする。
  新規行は出典に文化庁DB・加工した旨・利用規約へのリンクを示す。時代と解説は未登録とする。
- 広義史跡は座標と日本語Wikipedia記事を持つ遺跡、古墳、城跡等に限定する。
- 画像はWikimedia Commonsでライセンスを確認できるものだけを表示し、作者・ライセンス・出典を併記する。
- 利用条件の判断は `docs/tool-license.yaml` に記録する。

## Runtime differences

- 自己ホスト版は既定 port 8530。Cloud Runでは `PORT` を使用する。
- Cloud Runでは `SHISEKI_SUMMARY_DISABLE=1` とし、Wikipedia本文ブロックを表示する。
- `JALAN_A8MAT` がある場合のみ、地点に事前割り当てしたじゃらん大エリア（LRG）の宿泊リンクを
  詳細下部に表示する。LRGが未判定または曖昧な地点は都道府県リンクへフォールバックする。
- LRGはリポジトリルートの `scripts/generate-jalan-lrg.py` で全地点へ静的に付与する。境界データの版と
  商用利用条件は `docs/tool-license-jalan-lrg.yaml` を参照する。
- 確認済み割り当てはリポジトリルートの `data/jalan-lrg-overrides.json` に根拠・確認日付きで固定し、
  新規地点にLRGがなければ生成・検証を失敗させる。リポジトリルートで `uv run python scripts/check-jalan-lrg.py`
  を実行すると、onsen/omatsuri/shiseki 全件の欠落と不整合をオフライン検査する。
- 自治体判定は「国土数値情報（行政区域データ）（国土交通省）を加工して作成」した
  Geolonia `japanese-admins`（生成時のみ使用）に基づく。
- 全HTML entry pointに `data-site="shiseki-map"` のvisit-logタグを置く。Cloud Runから
  LAN内集計先へ到達できない点は `deploy-cloudrun.sh` に例外理由を記録する。

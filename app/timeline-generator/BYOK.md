# 本人APIキーによる生成の検証

追跡課題: `ats030-c5o5r`。2026-10-11時点ではオフラインの接続・制限検証まで実装しています。
実APIの品質・料金比較と一般公開は未完了です。通常の `public_server.py` 起動にはBYOKを接続しません。

2026-10-11の利用者指定により、開発用BYOKのデフォルトはGoogle AI Studioで発行したGemini APIキーです。
固定モデルは `gemini-3.5-flash-lite` です。Anthropicのキーは受け付けません。
条件と根拠は [tool-license.yaml](tool-license.yaml) の `byok_provider_review` にあります。
Googleの規約は18歳以上の開発者利用を要求し、18歳未満が利用しそうなAPIクライアントを制限します。
この変更は成人開発者の評価用で、年齢を限定しない一般公開への適合を承認するものではありません。
無料枠の入力・出力は改善や人手確認に使われる場合があります。本人の地域・契約条件を確認してから実行します。

## 経路とキーの寿命

`byok.py` は標準ライブラリだけを使い、証明書を確認するHTTPSで `generativelanguage.googleapis.com/v1beta/models/gemini-3.5-flash-lite:generateContent` に送ります。
接続先・モデルは固定です。環境プロキシ、リダイレクト、SDK、自動HTTP再試行、外部ツール、キャッシュ指定を使いません。
APIキーはヘッダーだけに置き、プロンプト、結果、ログ、設定、環境変数、SQLite、お試し台帳、バックアップへ保存しません。
キーへの参照を終了時に解放しますが、Pythonの文字列を物理的にゼロ消去する保証はありません。

`byok_pipeline.py` は処理ごとにspawnした子プロセスへキーを渡します。
検索補助、資料選別、生成、引用・年代照合、件数調整の全モデル工程へ同じ `ModelSession` を明示的に渡します。
引用・年代の機械検査と追加資料の照合を維持します。
BYOKでは先行生成と未使用記事への追加の自動再生成を止めます。資料は同じ処理工程で読みますが、この変更による品質差も比較対象です。
プロバイダー失敗や上限到達で処理を終了し、他モデル・運営AIへ切り替えません。

本人が承認した上限は、送信前に入力のUTF-8バイト数と出力トークン上限から保守的に予約します。
プロバイダーの使用量を受け取った場合だけ実トークンの有料標準単価による見積額へ精算します。
不明な使用量や送信後の通信失敗は予約額を上限として残します。
入力USD 0.30、出力（推論込み）USD 2.50 / 100万トークンで計算し、無料枠や暗黙キャッシュの割引は差し引きません。
`minimal` は推論ゼロの保証ではないため、出力上限に加えてモデルの最大出力枠65536トークンを推論用に保守的に予約します。
このため、低い承認額では実費が少なくても送信前に `cost_budget` で停止する場合があります。
使用量の候補出力・推論トークンを合算し、整数のUSD百万分の1へ切り上げます。
固定した料金でのAPI本文の試算であり、税・為替・将来の料金変更・他のアカウント利用を含みません。
料金やトークン仕様が変わった場合は予約式を再確認してから使います。

中止と時間切れで子プロセスを終了します。送信済み要求のプロバイダー処理や課金の取り消しは保証しません。
再起動時にはキー・受付・結果を復元せず、有料生成を再開しません。
親プロセスが落ちた場合の子の停止は配備側のプロセスグループ制御も必要です。

## 受付と負荷制限

接続には `ByokLimits.from_env()` が要求する全設定が必要です。
以下の値は比較試験用の例で、公開運用の実測値ではありません。

| 設定 (`TIMELINE_BYOK_` 接頭辞) | 試験値 | 制限 |
|---|---:|---|
| `CONCURRENT` | 1 | BYOKの同時処理数 |
| `STARTS` | 20 | 本人ごとの1分間の新規受付数 |
| `OWNERS` | 100 | 1分間の頻度管理対象数 |
| `RECEIPTS` | 100 | メモリ上の受付容量 |
| `TTL` | 3600 | 受付・結果の寿命（秒） |
| `TIME_LIMIT` | 3600 | 1件の処理時間（秒） |
| `FETCH_CALLS` | 100 | 検索・robots・記事・転送を合わせた取得回数 |
| `FETCH_BYTES` | 40000000 | 取得量（バイト） |
| `MODEL_CALLS` | 60 | モデル呼出回数 |
| `INPUT_BYTES` | 100000 | 1回のモデル送信本文のバイト数 |
| `OUTPUT_TOKENS` | 6000 | 1回の出力トークン上限 |
| `MAX_COST_MICROUSD` | 500000 | 1件の承認額の最大値（USDの100万分の1） |

未設定・ゼロ・型不正・範囲外を無制限として扱いません。
HTTPの頻度・応答量には既存の `PublicLimits` も適用します。
取得は ja/en Wikipedia のAPI、記事、robotsだけを許可し、記事は既存のDNS固定・robots確認を通します。
全取得スレッドで回数とバイト上限を共有します。失敗した記事取得は予約量を消費したものとして扱います。
大きすぎる応答の判定には上限を1バイト超える読取りが必要です。

BYOKとお試しを同じHTTPサービスに接続する場合は、同じ `GenerationSlots` を両ランタイムへ渡します。
異なる枠や未指定の枠では `make_server` が接続を拒否します。
同時数は `server_busy`、頻度は `request_rate`、取得上限は `fetch_budget`、モデル費用・回数は `cost_budget` で区別します。
別プロセスの私用ワーカー・比較測定はこの枠を共有しないので、一般公開前に配備側で競合を制御します。

Googleの無料枠で16回目の呼出しが429になったため、モデル送信開始を処理ごとに15秒以上空けます。
本人が確認した枠はRPM15、入力TPM250000、RPD500です。
処理内の直近60秒の入力トークンも250000以内へ制御します。
送信前は本文バイト数＋8192を入力トークン上限として予約し、確認できた使用量だけ精算します。
次の送信が枠を超える場合は古い呼出しが60秒の窓から外れるまで待機します。
これらは検証用の制御で、プロジェクト全体のRPM・TPM・RPDに適合した保証ではありません。
待機は処理・工程の時間上限に含み、中止や時間切れで未送信の呼出しを消費・費用予約しません。
Googleの制限はプロジェクト単位なので、別の端末や処理で使った分はこの間隔制御では数えられません。
429の限定したQuotaFailure情報だけから、日次枠は `provider_daily`、入力トークン/分は `provider_tokens`、
回数/分や分類できない制限は `provider_rate` にします。複数ある場合は日次枠を優先します。
エラー本文・キー・プロジェクト識別子は保存せず、429の呼出しを自動再試行しません。
実際の制限は [Google AI Studio](https://aistudio.google.com/rate-limit) で確認します。

## 認証付きHTTP契約

通常起動では無効です。接続試験には `make_server(..., byok=runtime)` を明示します。
既存のGoogle認証セッション、固定Origin、CSRF、本人ごとの頻度制限を使います。

| 操作 | 経路 | 本文 |
|---|---|---|
| 新規受付 | `POST /api/byok/receipts` | `receipt_id`, `query`, `api_key`, `max_cost_microusd` の4項目のみ |
| 状態・結果 | `GET /api/byok/receipts/{id}` | なし |
| 中止 | `POST /api/byok/receipts/{id}/cancel` | `{}` |
| 受領通知 | `POST /api/byok/receipts/{id}/received` | `{}` |

URL・モデル・owner・mode・運営設定をクライアントから受け付けません。
同じ本人・受付ID・正規化テーマ・承認額の再送は、保持中の受付を返し追加生成しません。
再試行には新しい受付IDと本人キー・上限の再送が必要です。期限終了後のID再利用に跨がる冪等性は保証しません。
受付はメモリだけに持ち、期限切れは次の受付/参照/終了時に除去します。定期清掃と公開UIは公開検証課題に残ります。
本人以外は状態・結果・中止・受領にアクセスできません。
原文引用・trace・キー・owner・入力テーマの保管用本文はHTTP受付に残しません。

お試しの残り枠はBYOK受付に適用しません。
BYOK新規・再送・中止・再試行でお試し台帳を変更しません。
運営AIへ切り替えるときは別の `POST /api/trial/receipts` を使い、既存のお試し受付が実行前に枠を確保します。
BYOK受付を運営AI用へ付け替える操作はありません。

## 実APIの比較

`byok_eval.py` は固定評価集合のテーマを1件ずつ実行します。
DBを開かず、キーは端末の非表示入力で受け取り、引数・環境変数・ファイルから読みません。
出力は権限600で新規作成し、存在する結果を上書き・自動再開しません。
結果の主要項目・既知の誤り・重複、呼出回数、トークン、費用、時間、コード/goldハッシュを記録します。
原文引用・trace・キーを結果ファイルに保存しません。

同じコード・gold・検索設定・取得上限・時間上限で比較します。
Wikipediaの本文は測定間で変わりうるため、この比較だけでは入力が同一だったとは断定しません。
各テーマで主要項目100%・既知の誤り0・重複0・資料処理完了を必要とし、失敗も比較から外しません。
固定6テーマとholdout3テーマを実行した後、独立した出典監査も行います。
1件の合格を経路全体の合格と扱いません。

本人キーと承認する費用がある場合だけ、まず1テーマを実行します。
既存モデルの測定と私用生成が動いていないことを確認してから運営モデルの比較を行います。

```bash
python3 byok_eval.py --route byok --theme 昭和 --max-usd 0.50 --output data/byok-eval/showa-google-free-byok.json
python3 byok_eval.py --route operator --theme 昭和 --max-usd 0.50 --output data/byok-eval/showa-google-free-operator.json
python3 byok_eval.py --compare data/byok-eval/showa-google-free-operator.json data/byok-eval/showa-google-free-byok.json --output data/byok-eval/showa-google-free-comparison.json
```

運営モデル側の金額0は外部AIのAPI料金だけを指します。電気代・検索・維持管理は残ります。
比較CLIは開発用です。公開受付から運営モデル比較へ移る経路はありません。
一般公開に必要なGoogleの年齢・用途条件への適合、本人契約の条件、表示、定期清掃、実負荷調整は `ats030-c5o5r` / `ats030-zioew` で追跡します。

前半は改修前の保存結果の監査です。改修後の観測結果と残る課題は末尾に記載します。

## 評価基準一覧

品質の基準は、測る時点によって4種類あります。基準の定義の正本はそれぞれの算出箇所です。この表は索引で、基準を足すときは算出箇所と一緒に更新します。

### 保存結果の自動評価

`quality_eval.py` で計算します。モデルは呼びません。詳細画面の「評価」欄と比較ページ `/quality`（API は `/api/quality`、更新の新しい50件）は、`job_quality()` が返す `axes` を表示のたびに計算して棒で示し、保存しません。総合点は作りません。

| 基準 | 測るもの | 算出箇所 | 表示箇所 |
|---|---|---|---|
| 主要項目の再現率 | `quality_gold.json` の主要項目のうち、年表に入った割合。語・年・日付のすべてが一致したときだけ入ったと数え、期間の外の項目は対象から外す | `evaluate_result()` の `recall` | 詳細画面、CLI |
| 欠落した主要項目 | 年表に入らなかった主要項目の名前 | `missing` | 詳細画面、CLI |
| 欠落の段階 | 欠落した項目の語と年が、引用元ページの同じ段落にあるかどうか（ある：候補生成か検査で落ちた／ない：検索か資料選択で落ちた） | `locate_in_sources()`（`--fetch-sources` のときだけ） | CLI |
| 既知の誤りへの一致 | 過去に見つかった誤りと同じ年・語の項目。「伝説」などの留保語があるときは数えない | `known_errors` | 詳細画面、CLI |
| 重複の疑い | 年と出典URLが同じで、片方の題名がもう片方に含まれる組 | `duplicates()` | 詳細画面、CLI |
| 出典の多様性 | 出典のサイト数と、最も多いサイトの割合 | `source_stats()` | 詳細画面（生成情報）、CLI |
| 出典の種類 | 一次/当事者・百科(二次)・個人投稿・未分類の件数。一次/当事者はテーマごとの `primary_domains` で判定する | `source_kind()` | 詳細画面、CLI |
| 打ち切り試算 | 先頭N組だけで止めた場合の再現率と、その組までの所要秒数。最終結果のうち、N組目までに採用された出来事だけで数える近似 | `replay()`（`--replay-batches 2,4,8` のときだけ） | CLI |
| 止まり方・処理時間 | `stop_reason`（`time_limit`・`processing_error` など）と所要秒数。再現率が低い結果とよく対応する | 保存結果の値 | 一覧、詳細画面、CLI |

`axes()` は上の基準を8つの軸（再現率、既知の誤り、重複、一次/当事者の割合、個人投稿の割合、最多サイトへの集中、件数／50件、処理時間／60分）に並べます。合否を付けるのは、目標がある軸だけです。再現率の目標 `target_recall` は人が決めた値だけを `quality_gold.json` に置きます。主要項目は欠落を見つけるための最小集合なので、全テーマで 1.0（1件でも欠ければ目標外）とします（ats030-it7yx）。既知の誤りと重複は0件を基準内とします。ほかの軸は量だけを灰色の棒で示します。

再現率・欠落・既知の誤りは、正解集合にあるテーマ（インターネット、Claude Code、コーヒー、ラーメン、平家物語、昭和）だけで計算します。ほかのテーマでは出典と重複の集計だけを出します。出典の集計は内容の正しさを判定しません。

### 生成時の検査

`timeline.py` が候補を年表に入れる前に掛ける条件です。満たさない候補は外すか、比較注記（`review_notes`）に回します。点数は出しません。回帰テストは `test_quality.py` です。

| 基準 | 内容 |
|---|---|
| 引用の実在 | 引用文が出典ページの本文にある |
| 年と出来事の対応 | 年代見出しと段落を一緒に扱い、背景に出てくる別の年を出来事の年にしない |
| 月日の実在 | 正確な日付は、出典に実際の日付があり、暦として正しいときだけ付ける |
| 伝承と史実の区別 | 伝説・伝承・諸説として書かれた内容を断定にしない。比較資料に伝説とあれば断定を見送る |
| テーマの範囲 | 入力テーマを広げない（関連モデルの出来事を製品本体の出来事にしない など） |
| 出典間の食い違い | 別資料との矛盾は消さずに比較注記に残す |
| 時代の偏り | 本文の抜粋を時代ごとに配分し、終盤の出来事が抜粋の上限で落ちないようにする |

### 人手の編集監査

この文書の前半で使った基準です。自動化していません。引用の実在率、年代の正しさ、テーマへの適合、主要な転換点の網羅、伝承と史料の区別、出典間の食い違いの提示、題名の読みやすさを見ます。件数の少なさだけでは不合格にしません。

## 結論

出典をたどれる短い読み物としては使えますが、「主要な出来事から歴史の全体像を読む」という目的には要改善です。
年代の取り違え、テーマの拡張、重要な出来事の欠落、出典間の食い違いの未提示が残っています。
文章の読みやすさより、年代と出来事の結び付けと網羅性を優先して改善すべきです。

## 重要な指摘

### 1. 2006年のSNS項目は、別々の年の出来事を混ぜている

保存結果はFacebookの一般向け展開とTwitter日本語版開始を2006年の一項目にまとめています。
[引用元のデジタルアーツ年表](https://www.daj.jp/history/internet/)では、この段落は2008年の項目に属します。段落内の2004・2006年はサービスの背景です。
[Twitterの公式発表](https://blog.x.com/en_us/a/2008/twitter-for-japan)は2008年4月22日、日本語の[開発ブログ](https://twitterjp.blogspot.com/2008/04/twitter.html)は日本時間4月23日の開始を記載しています。日付の時差とは別に、年表の2006年は誤りです。

実装のArticleParserで出典を再解析すると、4文字の「2008」見出しは残らず、背景の2006年を含む段落だけが残りました。
flush()が8文字未満の行を除外し、本文も年代を含む行に絞っているためです。年が本文中に存在することを確かめても、どの出来事の年かは検証できません。
生成時の中間入力・判定ログは保存されていないので、生成時にモデルがどの過程で誤認したかまでは断定しません。

1983年の項目も、[Internet Societyの説明](https://www.internetsociety.org/news/press-releases/2013/new-years-day-marks-30th-anniversary-of-major-milestone-for-global-internet/)に沿って「ARPANETがTCP/IPへ移行」と書く方が、単なる「標準化」より出来事を正確に表せます。
網羅性の面では、[CERNが説明する1989年のWWW誕生、1993年の公開](https://home.cern/science/computing/the-birth-of-the-web/where-web-was-born/)は有力な追加候補です。

### 2. Claude Code本体と、Claudeモデルの出来事が混ざっている

プレビュー公開は[Anthropicの2025年2月24日発表](https://www.anthropic.com/news/claude-3-7-sonnet)と整合します。
一方、「推論モードの提供開始」はClaude 3.7 Sonnetの出来事です。背景としては関連しますが、Claude Codeの更新と同じ扱いにすると対象がぼやけます。
[2025年5月22日の公式発表](https://www.anthropic.com/news/claude-4)にはClaude Codeの一般公開、IDE連携、SDKなどがあり、保存年表には一般公開さえありません。
現在の2項目はいずれも「2025年」表示です。短期間で変わる製品では、出典にある月日も残すと経過が分かりやすくなります。

### 3. コーヒーは伝承と史料の食い違いを表示する必要がある

1683年のウィーン初のコーヒーハウスは引用元に記載されていますが、[ウィーン市の資料](https://presse.wien.gv.at/presse/2011/11/11/wiener-kaffeehauskultur-ist-immaterielles-kulturerbe-der-unesco)は、1683年のコルシツキーの話に証拠がなく、史料で確認できる最初の店をディオダートによる1685年と説明します。
保存結果の「とされています」だけでは、伝承と確認された記録の違いは読み取れません。引用元に書かれているという理由だけで史実として採用することに限界があります。
900年の記録なども、引用元の留保を保つ必要があり、この監査では独立した原史料まで確認していません。

10件のうち3件が都市のコーヒーハウス開業で、最新は1888年です。「歴史と普及」というテーマなら、近現代の製造・流通・飲用文化を含める余地があります。
例えば[1938年のネスカフェ発売](https://www.nestle.co.uk/en-gb/media/newsfeatures/nescafe-75-years)、[1969年のUCCミルク入り缶コーヒー発売](https://www.ucc.co.jp/company/pressroom/pickup/20250716.html)などです。どれを採用するかは編集判断ですが、10件あるだけで全体像を満たしたとは言えません。

### 4. ラーメンは、出典にある主要項目を落としている

6項目とも[新横浜ラーメン博物館の年表](https://www.raumen.co.jp/rapedia/study_history/)に引用が存在しました。ただし、全件が同じページなので出典間の照合はできていません。
同ページには1937年の南京千両、1947年の久留米「三九」の白濁豚骨スープ、1958年のチキンラーメン発売もありますが、保存結果にはありません。
1958年の発売は[日清食品の公式資料](https://www.nissin.com/jp/company/news/4446/)でも確認できます。「多様な展開」を説明する上で、1989年のブームだけよりも、その前段の技術や商品を含める方が有用です。

## 実装で確認できたことと、未確認のこと

- 年代だけの短い見出しが欠落することを、実ページと現行パーサーで再現しました。
- 本文は1ページあたり先頭3000文字に制限されています。ラーメン資料では2005年の項目が約2952文字目にあり、2007年以降の項目は境界の後でした。近年の情報を落とす構造的な偏りがあります。
- 生成プロンプトは10件を求め、検証後に不足を補う処理はありません。資料中にあった項目が候補生成と検証のどちらで落ちたかは、保存結果だけでは分かりません。
- 照合用入力は出来事と引用で、見出しを含む周辺文脈や独立資料は渡されません。同じモデルによる引用一致の判定を独立した史実確認とみなすことはできません。
- 文章は短く年代順で、出典・引用にアクセスできます。一方、タイトルの「トルコでの開業」「オックスフォードの拠点」は、対象を「コーヒーハウス」と明示すると読みやすくなります。

## 改善の優先順

1. 見出しと段落を一緒に扱い、年と出来事の対応、伝承・推定・史料間の食い違いを検査する。
2. 入力テーマの範囲を保ち、公式・当事者資料を優先する。関連モデルなど背景情報は本体の出来事と区別する。
3. 時代別に候補を集め、主要転換点の欠落を確認する。少ない場合も件数合わせで推測しない。

生成機構の改善後も、現在保存されている結果は自動では変わりません。改善実装時には再生成と既存結果の扱いを別途決める必要があります。

### 観測

- **欠落の多くは出典の中で起きています。** current で欠落した25件のうち18件は、引用したページの同じ段落に語と年がありました。残り7件は出典にありませんでした（太平洋戦争、終戦、沖縄返還、以仁王、一ノ谷、壇ノ浦など）。改善は、検索を増やすより、候補生成と検査の取りこぼしを調べるほうが先です。
- **ラーメンとインターネットが後退しました。** ラーメンは v2 の83%から17%に、インターネットは33%から0%に下がりました。どちらも `processing_error` で止まり、欠落した項目はすべて引用済みの出典に載っています。
- **既知の誤りは current で再発していません。** v1 の Twitter 2006年と推論モード、v2 のエスプレッソーダ 2013年は、いずれも current の結果にありません。
- **平家物語に重複が1組あります。** 同じ出典・同じ年の「木曽義仲の入京と平家追討の院宣」と「木曽義仲の入京」です。出典は個人ブログ3件だけでした。

### 画面への反映

生成情報に「出典 Nサイト：サイト名 件数（多い順に3件まで）」を表示しました。決定的に数えられる事実だけを出し、点数や警告は出しません。

出典が1サイトに偏っていても、再現率が低いとは限りませんでした。ucc.co.jp だけのコーヒーは67%、raumen.co.jp だけの v2 ラーメンは83%です。そのため偏りは警告にせず、中立な一行にしました。低い再現率とよく対応したのは止まり方です。`time_limit` と `processing_error` には既存の注意文があるので、新しい警告は加えていません。

### 評価の限界

- 正解集合はテーマごとに3〜10件の最小集合です。再現率が高くても、示せるのは「主要項目を外していない」ことだけです。
- 照合は語・年・日付の一致で行います。表記ゆれ（旧字体の來々軒・淺草など）は語を足して対応しています。未登録の言い換えは欠落と数えます。
- 照合語は1語の一致で足りるため、広い語は誤合格を生みます。gold v2（2026-10-03、ats030-r0spm）で、現行6結果の一致イベントを人が確認し、誤合格3件（昭和 終戦←「東洋大学の新制制度への移行」の「敗戦」、TCP/IP移行←BSD 4.2、WWW←NTT社内ページ）と言い換え漏れ2件（チキンラーメン←「日本初インスタントラーメン」、都落ち←「木曽義仲の入京」）を直しました。缶・豚骨・沖縄などの広い語も具体語に絞りました。v1 の再現率とは直接比べられません。
- コーヒーとラーメンの根拠は ucc.co.jp・raumen.co.jp にほぼ依存し、平家物語・昭和は Wikipedia だけです。ラーメン博物館の開館は博物館自身の資料による自己申告です。インターネットは1994年以降、昭和は経済・社会の項目を含みません。
- 処理経過を記録していないため、候補生成で落ちたのか検査で落ちたのかは区別できません。
- 状態が failed のジョブは、保存されている旧結果を評価しています。

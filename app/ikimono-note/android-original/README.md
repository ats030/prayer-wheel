# 元写真を渡すAndroid補助アプリ（試作）

AndroidのDocumentsProviderとして、読み取る許可のある端末内写真を
`写真名.jpg.zip` などの文書として表示する。利用者が写真を選んだ時だけ
`MediaStore.setRequireOriginal()` で原本を読み、メモリ上で1枚入りZIPを作り、
メモリを読む読み取り専用のプロキシファイルでブラウザへ渡す。
ブラウザが必要とするサイズ取得・シークに対応する。画像はデコード・再圧縮しない。
ZIPはSTORED方式で、写真サイズとヘッダーから正確なZIPサイズを選択時に返す。
サイズ不明を0バイト扱いするChromiumの挙動を避けるため、サイズをnullにしない。
写真へのアクセスとACCESS_MEDIA_LOCATIONの両方が必要。権限がない場合は
一覧を空にし、原本読み取りが失敗しても位置情報を除いた写真へ切り替えない。

既存Webの「元写真ZIPを選ぶ」を利用する。ログイン、APIキー、履歴はBraveに
引き続き保存される。ネットワーク権限、WebView、JavaScriptブリッジ、外部SDK、
写真の永続コピーは追加しない。提供した文書は利用者が選んだ別のアプリにも
読み取れるので、位置情報を含むことをセットアップ画面で説明する。

Android 10以降。端末内のJPEG/PNG/WebP、写真とZIPそれぞれ15MiB以下。
Android 14以降は「選択した写真」へのアクセスも扱う。選択写真を増やす場合は
補助アプリの「使う写真を許可する」を再度押す。
クラウドだけにある写真は対象外。ZIP名で一覧表示するためサムネイルは提供しない。
Pixel Braveでの原本取得・ファイル選択画面の実機確認はリリース後に必要。

0.1.1のセットアップ画面には「元写真の位置情報を確認する」がある。
専用Providerから同じ写真を選び、元写真ZIP内の写真をAndroid標準ExifInterfaceで
読み、GPSあり・タグなし・値不正・EXIF解析失敗を表示する。
Web側のPython/Pillowと独立した解析なので、取得段階とWeb解析段階を切り分けられる。
SHA-256の先頭16桁を確認コードとして双方の端末画面に表示し、同じバイトか確認する。
診断用のサーバーログへコード・座標を送らず、現在地を取得しない。
実機フィードバックでプレビューは出るがGPSを読めないことを確認している。
0.1.1は診断機能の追加であり、実機GPS問題の修正済みを意味しない。

## ビルド

追加のランタイム依存なし。Temurin JDK 21、Android SDK Platform 35 r2、
Build Tools 35.0.0を利用する。導入条件はtool-license.yamlに記録。
`build.sh` のIKIMONO_ANDROID_*環境変数で配置を指定できる。

署名鍵はリポジトリに入れず、既定で
`~/.local/share/ikimono-android/signing/release.jks` と同フォルダの
`password` ファイルを使う。鍵とパスワードは0600で管理・バックアップする。
鍵を失うと同じアプリへ更新できないため、作り直して既存のAPKを置き換えない。
この鍵はこの補助アプリ専用で、Webサービスの認証秘密とは別。

`bash build.sh` は署名済みAPKを `../static/downloads/` に出力する。
バージョンを変更する時はmanifest、build.sh、配布ページを同時に更新する。
公開済みバージョンのAPKを別の内容で再公開しない。

## 検証

`test.sh /path/to/original.jpg` は標準JavaでZIP処理を実行し、原本のバイト一致、
空入力・上限・危険なファイル名を確認する。Androidの権限やMediaStoreの挙動は
このテストでは証明できない。

実機では補助アプリを開き、写真・撮影場所を許可し、Braveで
「元写真ZIPを選ぶ」→ ファイル選択画面のメニュー →「生きものノート 元写真」
から写真を選ぶ。Web側の緯度経度表示、識別後の履歴・地図で確認する。
権限を取り消した場合に一覧が空となり、位置なしへ黙って切り替えないことも確認する。

## 戻す

補助アプリをアンインストールするとファイル選択画面の入口が消える。
Brave内の既存記録、ログイン、設定は変更しない。

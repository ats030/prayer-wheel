# 品目写真

全651品目が写真欄の対象です。`frontend/images.json` の確認済み写真を優先し、
未登録のWikidata品目は既存の `/api/wikiimage?qid=Q…` を使います。
公式品目に架空のQIDを付けません。既知の誤写真や許諾不明の候補は旧経路でも表示しません。
写真登録が取得できない場合も一覧・地図は利用でき、写真欄から再試行できます。

2026-09-29の監査では、旧P18/P373経路で画像URLとライセンスを解決できる候補は119/651件
（18.3%）でした。確認済み登録は229/651件（35.2%）、うち公式品目102件です。
これはメタデータと品目対応の確認率であり、利用者の回線での画像ダウンロード成功率ではありません。
集計と未登録理由は `data/images.json` に保存しています。
同日のHTTP検査では、登録229件すべての画像URLが画像として成功応答しました。

写真候補は既存curationの記事タイトル、公式品目の同名記事、WikidataのP18/P373です。
本文記事の写真を優先しますが、転送先が一般的な食材、地名、別の料理であれば採用しません。
許可する別名、除外ファイル、地域による料理の取り違えは `data/image_review.json` に記録します。
自治体庁舎、店舗外観、食品レプリカなどで件数を増やしません。
茶畑や実際の制作工程など、品目に対応する写真には内容の説明を付けます。

各画像に作者・クレジット・指定された帰属表示、ライセンスへのリンク、Commonsのファイル出典を表示します。
許諾範囲は [tool-license-photos.yaml](tool-license-photos.yaml) に記録しています。
元画像の加工はしません。縮小画像の読み込みが失敗した場合だけ、同一ファイルの元画像を試します。
APIの正のキャッシュは7日で更新し、失敗した画像はキャッシュから削除します。
失敗を永続キャッシュせず、写真欄の「再読み込み」から再試行できます。

更新時は以下を実行し、候補の品目対応と写真の内容を確認してから公開します。
新しい監査では別のキャッシュディレクトリを使い、`image_review.json` の確認日も更新してください。

```sh
python3 scripts/build_images.py --cache /tmp/tokusan-photo-cache
python3 -m unittest discover -s scripts -p 'test_images.py'
```

API応答はリポジトリ外に保存します。50件ごとの照会、maxlag=5、429/503の再試行と
識別可能なUser-Agentを使います。画像自体を一括保存する仕組みは追加していません。
登録データ、審査記録、公開JSONは一緒にコミットします。

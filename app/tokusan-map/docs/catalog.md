# 掲載データ

既存のWikidata候補は `frontend/tokusan.json`、掲載・除外の判断は
`data/curation.json` に保持します。追加の公式出典品目の正本は
`data/official.json` です。両方から `scripts/build_db.py` がSQLiteを生成します。

公式出典品目は、名称・分類・産地・短い説明・公式出典を必須にします。
全国販売されていても、公式情報で地域の産品・名物・土産と確認できれば掲載します。
製造元が違うだけの同じ名物は増やさず、独自の名前と特徴を持つ商品は別品目にします。
一般的すぎる料理名、既存品目の別表記、海外産品、全国単位の産品は今回の追加から除きました。

主な出典は農林水産省のGI登録産品、うちの郷土料理、にっぽん伝統食図鑑です。
木材は林野庁、花卉は農林水産省の産地紹介を利用します。
`source_checked_at` は取得・確認日です。分類はサイト用に編集しています。
名称は出典から取得し、説明は特性の短い抜粋、または産地と主な食材から編集しています。
写真・調理手順・第三者提供のレシピを転載していません。

`local-*` は追加品目に最初の登録時に割り当てる安定IDです。
既存APIの `qid` フィールドにもこのIDを返しますが、WikidataのIDではありません。
名称や出典を修正するときはIDを変えません。Wikipedia記事がない品目には
WikidataリンクやWikipedia画像取得を追加しません。

追加品目の地図上の点は県庁の代表座標です。具体的な産地や伝承地域は
`production_area` に残し、詳細に表示します。工場や販売店の所在地を意味しません。
県庁位置の点を開くと、県内の地域を選んでから品目を選べます。地域フィルターも
同じ分類を利用します。分類には出典の産地を優先し、既存品目は市町村・産地を使います。
県名の繰り返しと空白だけを整え、複数地域の表記は保持します。出典が県名・県全域と
している場合は「県全域」、産地の詳細がない既存品目は「県内の地域未詳」と表示します。
これは出典に基づく閲覧用の分類であり、行政が定めた統一広域区分ではありません。
地域ごとの座標は未登録のため、県庁の代表位置とその注記を引き続き使います。

```sh
python3 scripts/build_db.py
python3 scripts/verify_catalog.py
python3 scripts/verify_catalog.py --check-sources
```

2026-09-29の拡充で651件・15分類、47都道府県それぞれ7件以上になりました。

生成前に分類・出典・必須項目・重複・都道府県境界との一致を検証します。
生成したDBは一時ファイルから置換します。DBとサーバーの変更は同時にデプロイし、
ロールバック時も同じコミットのサーバーとDBを使います。

# Amazonリンク

詳細の「関連商品」に、品目名をそのまま検索語にしたAmazonリンクを表示します。
アフィリエイトが未設定ならタグなしの通常の検索リンクにします。有効な場合だけ
広告表示とAmazonアソシエイトの収入に関する表示を添えます。
検索結果にその品目があることは保証しません。価格・商品写真の取得は行いません。

ローカルでは有効な `~/.config/ikimono-note/settings.json` の
`affiliate.url` を利用します。`TOKUSAN_AMAZON_URL` があればそちらを優先します。
形式は `https://www.amazon.co.jp/s?k={query}&tag=運営者のタグ` です。
環境変数を空文字にすると広告を無効にし、通常の検索リンクにします。タグはリンクに表示される公開情報で、
API鍵を読み込む必要はありません。Cloud Runにはこの環境変数を設定します。
新しいサイトのアソシエイト登録状況はアカウント管理画面で確認する必要があります。

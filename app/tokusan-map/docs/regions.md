# 県内の地域

47都道府県について、公的な観光案内から県ごとに一つの区分を採用する。
採用URL・確認日・地域ID・地域名・産地との対応語は `data/regions.json` に保存する。
全国で行政区分を揃えることは目的としない。北海道は道央・道南・道北・道東、
愛知県は名古屋・尾張北部・尾張西部・知多・西三河・東三河・奥三河を使う。
観光案内が同じ市町村を複数の地域に含める場合もある（例：京都府福知山市）。
長崎県の本土6区分に、同じ公式サイトで案内する五島・壱岐・対馬を加える。
表示上の「エリア」は省き、区切り記号を「・」に整える。地域IDは表示順の変更や
地域名の修正で付け直さない。今回は228区分を登録した。

## 分類と検索

品目の `production_area`、それがなければ既存の `city` / `place` を使う。
代表座標、商品名、県庁所在地から地域を推測しない。
対応が確認できる市町村・地区・地域語を採用区分に対応づけ、該当地域IDをすべて残す。
短い地域名が別の市町村名の一部に含まれる場合は根拠にしない。
例：東大阪市は河内、安芸高田市は芸北として扱う。
長岡市（中越地方）のような括弧内の所属説明は、市町村を越える産地の指定と扱わない。
中越地方だけの指定は、対応する複数の観光区分に含める。

`region_scope` は次の3状態とし、`region_ids` と `region_basis` をDBに保存する。

- `regional`：根拠のある地域IDに所属する。各該当地域で検索できる。
- `prefecture`：県内全域、県全域などと明記されている。県内の各地域で検索でき、県全域だけでも絞れる。
- `unknown`：県名だけ、県内という表記だけ、または区分との対応を確認できない。県全体の一覧と地域未詳の選択肢に表示し、個別地域には含めない。

一覧は品目ごとに一度だけ表示する。地域の件数には県全域を含むため、複数所属も含めて
地域別の件数を合計しても県の品目数にはならない。地域が未詳でも品目を削除しない。
広い表現をどの観光区分に対応づけるか確認できない場合は、無理に割り当てない。
元の詳細産地と出典は保持する。分類語は確認済みのカタログと公的案内を基に整備しており、
未知の産地語が追加された場合は未詳として残りうる。

## 参照資料の利用判断

2026-09-29に各採用ページの地域名と市町村の対応を確認した。
公式観光サイトの地図画像、写真、紹介文、レイアウト、データベース全体は転載しない。
事実としての名称と地理的な関係を参照し、対応表を本アプリで編集した。
サイト全体のオープンライセンスや、紹介文の商用転載が認められているとは判断しない。
文化庁の[著作権制度の解説](https://www.bunka.go.jp/seisaku/chosakuken/seidokaisetsu/seminar/2024/pdf/94141401_01.pdf)で、
単なる事実・データは著作物から除かれることを確認した。
無料で閲覧できる公開情報の事実参照に用途を限定し、新しい有料API・実行時依存は追加しない。
採用した個々の出典は地域選択欄と公開 `regions.json` から参照できる。

## 再生成・検証

```sh
python3 -m unittest discover -s scripts -p 'test_*.py'
python3 scripts/build_db.py
python3 scripts/verify_catalog.py
go test ./...
```

DB生成時に47県・地域ID・出典を検証し、分類根拠を再計算して公開レジストリも生成する。
DB、APIサーバー、JS、公開レジストリを同時に更新する。地域分類を戻す場合も同じ単位で戻す。
マーカーの一品目一地点・非集約・非オフセットと、産地代表点の座標は変更しない。

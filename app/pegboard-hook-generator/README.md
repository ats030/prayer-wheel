# 有孔ボードフック ジェネレータ

寸法を指定すると有孔ボード用フックの STL を書き出す、単一HTMLのツール。
サーバー処理はなく、ブラウザ内だけで完結する。

```
open index.html          # これだけ。ビルドもインストールも不要
```

## なぜ作ったか

`~/pCloudDrive/CAD/PrintableFiles/` には `Hook-1-10` / `Hook-1-20` / `Hook-1-30` /
`Hook-1-10-30` … と、**1つのパラメトリックモデルを手で離散サンプルしたもの**が
個別ファイルとして並んでいる。BOOTH でもそれぞれ別商品として出品しており、
売上上位を占めている (フック系だけで累計38件) 一方、平均単価は98円だった。

離散サンプルを並べる代わりに、寸法を生成できるツールとして売れば単価を上げられる。
サーバーを持たなければ維持費もかからない。それがこのツールの位置づけ。

関連 issue: `ats030-y9fb`

## 設計上の制約

外部依存を一切持たない。three.js も含めて何も読み込まない。理由は2つ:

- 購入者は zip を解凍してローカルで開く。CDN を参照していると、オフラインや
  数年後のリンク切れで動かなくなる
- 配布サイズを小さく保ちたい

そのため 3Dプレビューは canvas 2D の画家のアルゴリズムで自前実装している。
モデルは52三角形しかないので、これで十分間に合う。

## 形状の作り方

YZ平面上の中心線に沿って矩形断面をスイープする (`buildPath` → `sectionsOf` →
`buildMesh`)。屈曲部は法線の平均でマイター接続する。

この方式を選んだのは、**必ず閉じたメッシュになる**から。2Dブーリアンやオフセット
＋耳刈り取りは、パラメータの端値で自己交差して穴あきメッシュを吐きうる。売り物な
ので、どの寸法でも水密であることを優先した。

座標系:

- `+Y` = ボード前面から手前 (物を掛ける側)、`+Z` = 上、`X` = 幅方向
- ボード前面が `y=0`、ボードは `y=-boardT` まで奥に続く
- スパイン背面が `y=0` に接する

## 既定値の根拠

既存製品の STL を実測して決めた。

| 項目 | 実測値 | 備考 |
|---|---|---|
| 全幅 (X) | 5.0mm | Hook-1-10/20/30 すべて共通 |
| 全高 (Z) | 38.0mm | 同上 |
| 全奥行 (Y) | 28.9 / 38.9 / 48.9mm | 10mm の等差 |
| ペグピッチ | 25mm | 日本の有孔ボード規格 |

## 検証

```
node verify.js
```

`index.html` の `<script>` を切り出してそのまま評価するので、実装をコピーせずに
本体を検証している。本体を直せば検証も追随する。見ているのは:

- 各辺がちょうど2枚の三角形に、逆向きで共有されているか (水密・多様体)
- 法線の向きが揃っているか、体積が正か、縮退三角形がないか
- 奥行を10→20→30と変えたとき、全奥行がちょうど 10.000mm ずつ増えるか
- 有効奥行の定義 (スパイン前面から先端内側) が指定値と一致するか
- バイナリSTLを読み戻して寸法が一致するか、法線が単位ベクトルか

端値 (奥行80 / 先端角150° / 先端長0 / 幅20厚12 / 薄板ボード) も含めて8形状で回す。

UIは Playwright で別途確認している (`/tmp` のスクリプト、恒久化は未実施)。

## 既知の相違・未実装

- **全高が既存製品と違う** (生成 30.0mm / 既存 38.0mm)。既存品はアームより下に
  スパインが 5mm ほど伸びており、それが回り止めとして効いていると思われる。
  本ツールは中心線1本のスイープなので、アーム根元から分岐する回り止めを出せない。
  → `ats030-y9fb.5`
- **先端角度の解釈**。既存商品名の「曲げ：90°」「曲げ：30°」がどの基準の角度か、
  メッシュからは確定できなかった (実測は水平から約48°)。本ツールは「アームからの
  角度、90=垂直、90超で内向きに倒れる」と定義し直している。出品前に原設計の
  意図と突き合わせること。
- 面取り・フィレットなし。既存品は全体にフィレットが入っている。

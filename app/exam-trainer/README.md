# exam-trainer

資格試験・検定（まず G検定）の練習を、問題生成ではなく**学習の管理**として回す。port 8522。

シラバス項目ごとに Web から根拠を集め、根拠に紐づいた問題だけを出題し、解答履歴から
間隔反復で復習キューを作る。問題を作るだけなら市販の AI で足りるので、価値は履歴の側にある。

```
シラバス          素材            問題              学習
──────────      ──────────    ──────────────    ──────────────
1.1 定義     →  SearXNG    →  抜粋から生成   →  出題（verified のみ）
1.2 動向        trafilatura   機械チェック       解答を記録（追記のみ）
2.1 教師あり    ~/cache       検証パス           SM-2 で次回を決める
                              verified / held    弱点ツリー
```

## なぜこの形か

### 出題できるのは検証を通ったものだけ

`question.status` が `verified` のものしか出題されない。生成直後は `draft`、検証で答えが
割れたら `held`（人間の確認待ち）。**間違った正解は疑われずに暗記される**ので、記事の誤りより
害が大きい。writing の evaluate は advisory（保存も書き出しも止めない）だが、ここは出題を止める。

### 根拠のない問題は存在させない

問題は `source_refs`（URL）と `evidence`（根拠の抜粋）を持つ。生成時は抜粋を渡し、
その抜粋だけで答えが決まる問題を作らせる。抜粋にないことを問う問題は捨てる。

### 過去問は複製しない

集めるのは解説記事と一次情報であって、過去問の文面ではない。G検定の本試験問題は非公開だし、
問題文の複製は権利上まずい。シラバス項目 → 一次情報 → 自前の問題、という経路だけにしている。

### 機械チェックを LLM より先に置く

`checks.py` は正解が1つか、選択肢が重複していないか、「上記すべて」型が混ざっていないか、
**正解の選択肢だけが長くないか**を決定的に見る。最後のものは、正解が一番長い問題が
「内容を知らなくても当てられる」ため。ただし日本語では定義を問う正解が説明的になりやすく、
比 1.6 では普通の問題が落ちたので 2.0 にし、選択肢の平均が12文字未満のときは判定しない
（短い選択肢では1語増えるだけで倍になる）。

### 生成は「安い検査を先、高い検査を後」の順に通す

```
抜粋 → 生成 → 機械チェック → 根拠の照合 → 重複判定 → 検証パス → verified
                  (LLM不要)      (文字列)     (埋め込み)   (2回目のLLM)
```

決定的で速い検査を先に置く。形の壊れた問題をモデルに検証させると、モデルは形ではなく
内容を判定してしまうし、そもそも捨てるものに2回目の呼び出しを払う理由がない。

**根拠の照合**は、生成が返した `evidence` が抜粋に実在するかを見る。モデルは「引用しろ」と
言われても言い換えるので、句読点と空白を落とした包含判定にしている。20文字未満は偶然
一致しうるので受け付けない。ここで落ちたものは `held` ではなく破棄する — 引用の捏造は、
このアプリが防ごうとしている失敗そのものだから。

**検証パス**は、抜粋と問題だけを見せて別途解かせる。作問側と答えが割れたら `held`、
「抜粋から一意に決まらない」と言われても `held`。同じプロンプトの中で自己採点させないのは、
1ターンで自分の答えを読み返したモデルはほぼ必ず自分に同意するからで、それは検査ではない。

Ollama に繋がらず検証を実行できなかった場合も `held` にする（fail closed）。検証できない
検証では正解の一致だけでなく、問題がシラバス項目の知識を直接問うかも確認する。記事中に
根拠があっても、周辺的な逸話や項目外の知識を問う問題は `held` にして出題しない。モデルが
範囲判定を返さなかった場合も fail closed として `held` にする。

複数の素材がある場合は、各素材の最初の抜粋を一巡してから次の抜粋へ進む。DBの取得順で
先頭になった1記事だけから目標数を埋めず、独立した出典へ問題を分散させるためである。


問題が素通りするなら、ゲートを置いた意味がない。

### まとめて積むときは弱点から、上限つきで

シラバスを一通り埋めるのに項目数ぶん操作させても仕方ないので、目標数に満たない項目を
まとめてキューに積める。積む対象と順序には理由がある。

- **葉ノードだけ**を対象にする。親（「2」）は子を集約して弱点ツリーに出すためのもので、
  そこにも問題を作ると子と内容が重複する
- **弱点の順**に積む。間違えている項目 → 一度も出題していない項目 → 全問正解の項目。
  学習の管理という狙いに合わせると、埋める順序はこれ以外にない
- `verified` だけを数える。`held` や `draft` を数に入れると、出題できないのに
  「足りている」と判断して、解くものが無いまま終わる
- **一度に積む数に上限**を置く（既定8）。ワーカーは1件ずつ処理し、1項目に数分かかる。
  上限がないとキューが何時間深いのか分からなくなる

積む前に対象が画面に出る。何が始まるか分からないまま数十分のキューを作らせない。

### 問題文に「抜粋における」と書かせない

最初の実生成で `抜粋における「汎化誤差」の説明として正しいものはどれか` という問題が出た。
解答者に抜粋は見えないので、これは画面にない文書についての読解問題になってしまう。
プロンプトで禁じたうえ、`checks.py` でも機械的に弾いている（決定的に検出できるものを
プロンプトの言うことを聞くかどうかに賭けない）。

### SM-2 で始める

FSRS のほうがよく当たるが、パラメータを当てるための履歴が初日には無い。SM-2 は何も要らずに
「毎日全部復習する」失敗を防げる。`review` には FSRS が必要とするもの（時刻・正誤・所要時間・
grade）を残してあるので、あとで差し替えて履歴の上から再生できる。

失敗したカードは同日ではなく翌日に戻す。同じ日に出し直すと短期記憶を測るだけで、
本当に期限の来たカードを押しのける。

### 正答率は直近の解答だけで見る

全試行を平均すると、最近の改善が昔の間違いに埋もれる。次に何を勉強するか決めるには逆効果なので、
`node_stats` は問題ごとに最新の1件だけを数える。親ノードには子孫の解答を合算する。

## 別の試験を足すとき

試験は「シラバスの木 + 根拠素材」でしかないので、追加はシラバスを貼るだけ。
ただし**成立するかどうかは検定の知名度ではなく、その分野の一次情報が Web にあるか**で
決まる。実測した所感を残す。

素材の取れ方を先に測る（`SearXNG` で検索して本文が抜ける記事が何本あるか）。
候補12件を測った結果、検索ヒット数はどれも同じ8件で差がつかず、**本文が抽出できた
本数と総文字数**で分かれた。

| 見るところ | なぜ |
|---|---|
| 本文が抜ける記事が3本以上 | 1本しか無いと同じ節から重複した問題ばかり出る |
| 事実の記述が多いか | 「合格体験記」「受験案内」ばかりのページは文字数があっても問題にならない |
| 出題範囲が公開されているか | シラバスの項目名が検索語になるので、範囲が曖昧だと素材も曖昧になる |

食品・飲料系（日本酒・紅茶）や観光系（京都）は、検定と無関係に解説記事が厚いので
素材が集まりやすい。逆に、検定名でしか語られない分野は、検定の宣伝ページばかりが
集まって問題にならない。

### 素材は URL で直接入れられる

検索が唯一の入手経路だと、上流が止まった時点で生成が完全に止まる。問題バンクの
「素材を追加」で、項目にページの URL を直接渡せる。

- 検索が止まっていても素材を入れられる
- 公式の解説ページなど、検索結果より確実な出典を選べる
- 素材のある項目では `materials.ensure` が検索をスキップするので、以後の生成で
  検索は走らない

実測: 上流が全滅している状態で、Wikipedia の4ページ（計30,052字）を 3.1 に入れて
生成したところ、採用5 / 破棄1 で通った。取り込みは検索経由と同じ `extract_url` を
使うので、文字化け判定も同じように効く。

### 素材収集は検索エンジンのレート制限に当たる

SearXNG は上流の検索エンジン（brave / duckduckgo / google / startpage …）を束ねている
だけなので、短時間に検索を重ねると上流側が止める。**止まっても SearXNG は 200 と
空の結果を返す**ため、「その話題の記事が無い」と区別がつかない。実測で
`Suspended: too many requests` / `CAPTCHA` に到達し、生成が素材0本のまま done になった。

そこで空の結果が返ったときは `unresponsive_engines` を読み、レート制限なら
「時間をおいて再実行してください」と理由を出す。話題が無いなら諦める、制限なら待つ、で
取るべき行動が逆になるため、この2つを同じメッセージにしない。

運用上は、**一度に多数の検定を立ち上げない**。素材は取れた時点で DB に保存され、
90日は再収集しないので、立ち上げの山を越えれば検索の頻度は下がる。

なお、**過去問を載せているサイトはブロックする**（`web.BLOCKED_HOST_HINTS`）。
問題は一次情報から自前で作るのがこのアプリの前提で、他人の問題を取り込む経路は置かない。

## 構成

| ファイル | 役割 |
|---|---|
| `db.py` | SQLite のスキーマと接続。`PRAGMA user_version` で前進マイグレーション |
| `bank.py` | 試験・シラバス・問題・出題キュー・弱点集計。DB に触るのはここだけ |
| `srs.py` | SM-2 |
| `checks.py` | 問題の形の検査（LLM 不要） |
| `web.py` | SearXNG 検索 + trafilatura 抽出、抜粋への分割 |
| `materials.py` | 収集した素材の保存。90日で再収集 |
| `generate.py` | 生成・根拠照合・重複判定・検証パス |
| `jobs.py` | 生成の永続ジョブ。ワーカースレッドが1件ずつ処理する |
| `ollama_client.py` | chat(JSON) と embeddings |
| `app.py` | FastAPI ルート |
| `templates/`, `static/` | Linear UI（トークンは writing の DESIGN.md 由来） |

## 画面

- **解く** — 期限切れの復習を先に、なければ新規。A〜F キーで解答、Enter で次へ
- **弱点** — シラバス項目ごとの正答率。赤い枝から直接その範囲を解きに行ける
- **問題バンク** — 状態別の一覧。`held` を確認して出題可にするか破棄する。「生成する」で
  シラバス項目を選ぶと永続ジョブが走り、画面を閉じても続く（1問あたりモデルを2回呼ぶので
  数分かかる）。同じ項目に対する二重投入は既存のジョブに合流する。
  「不足している項目をまとめて」を選ぶと、目標数に満たない項目をキューに積む
- **試験の設定** — 試験の追加とシラバスの登録

## 公開画面と管理画面

考古検定入門向けのPDF販売準備と無料10問の体験は
[`docs/kouko/release-guide.md`](docs/kouko/release-guide.md)を参照。
「教材を探す」で考古検定を選び、無料10問と`/kouko/materials`のPDF・資料へ進める。
exam-trainerにアクセスできる利用者全員が、未校閲の全50問PDFも閲覧できる。
校閲状態は画面に表示し、通常の学習バンクには追加しない。

トップ(`/`)と「教材を探す」(`/products`)から、他の検定にも同じ構成で進める。
各教材には紹介、無料10問、解説の見本、PDF・原稿一覧があり、ログイン不要で閲覧・保存できる。
考古の既存URLはそのまま使える。

| 検定 | 教材URL | 収録数 |
|---|---|---|
| G検定 | `/products/g` | 50問 |
| 日本酒検定 | `/products/nihonshu` | 31問 |
| 歴史能力検定3級 日本史 | `/products/rekishi-3` | 50問 |
| 世界遺産検定3級 | `/products/sekai-isan-3` | 29問 |

これらは既存バンクの`verified`かつ四択・出典付きの問題をコピーした未校閲の教材。
`verified`は人による校閲、出典本文の再確認、商用利用条件の確認を意味しない。
保留・却下・下書き、出典なし、四択以外の問題は収録せず、分野を一巡する順で最大50問にする。
元の問題ID、出典URL、登録状態と保存済み根拠は教材JSONに保持し、解答履歴は書き出さない。

教材の正本は`src/exam_trainer/products/<教材ID>.json`で、学習バンクと独立して更新する。
PDFと原稿の再構築は`~/.venv/bin/python app/exam-trainer/scripts/build_products.py`。
既存バンクからの初回書き出しには`--export-bank ~/data/exam-trainer/bank.sqlite`を付ける。
書き出しはSQLiteをread-onlyで開く。既存教材の置換は既定で拒否し、未校閲教材のみ
`--replace-drafts`で明示的に置換できる。校閲記録CSVと販売原稿の手修正は再構築で上書きしない。
各教材の`release-guide.md`に校閲と販売の手順を記載している。販売価格は未定で、出品はしていない。
各教材のSHAに対する校閲・出典条件確認と、有効なBOOTH商品URLが揃ったときだけ購入リンクを表示する。
教材内容を変更すると販売の承認は失効するが、アプリ利用者の原稿閲覧は続けられる。
資料の教材SHAとファイルSHAは`docs/<教材ID>/artifact-state.json`に記録する。
旧版や未確認の手修正がある資料は「版の確認・更新待ち」と表示し、配信は409で止める。
販売原稿の内容が現在の教材に合うことを確認したら、再構築に`--confirm-sales-copy`を付ける。
これは原稿の版の照合であり、人による問題の校閲・販売の承認とは別である。
考古の再構築では手作成の販売原稿と販売手順の版を維持する。両方を現在の教材に合わせて
確認したときにだけ、`build_kouko.py`に`--confirm-copy`を付けて版を記録する。

今回の展開では新しい依存、外部データ取得、ネットワーク公開経路は追加しない。
使用ツールの条件は[`docs/tool-license.yaml`](docs/tool-license.yaml)と
[`docs/kouko/tool-license.yaml`](docs/kouko/tool-license.yaml)を引き継ぐ。
新4教材の出典の利用条件は未確認であり、販売前の確認対象とする。

- 公開: `/`・`/products`（教材選択）、`/study`（学習）、`/weakness`（弱点）
- 管理: `/admin/bank`（問題バンク）、`/admin/settings`（試験設定）
- 管理ログイン: `/admin/login`

日々の演習は「学習を続ける」から開く。旧`/?exam_id=...&node=...`や`/?node=...`は
学習画面として継続利用できる。教材画面には現在地を示す共通ナビを置き、
各検定の「10問を試す」を主操作にする。体験結果から全問PDFを直接保存できる。
資料画面は学習用PDF2種類を先に表示し、原稿・販売説明・校閲記録など5種類を
「制作資料」に折りたたむ。アクセス条件、未校閲表示と資料の版の照合は維持する。
画面設計の基準は[`DESIGN.md`](DESIGN.md)。

管理画面と変更系APIは `EXAM_TRAINER_ADMIN_TOKEN` で保護する。未設定時は管理操作を
fail closedで拒否する。ログイン後はHTTP-only・SameSite=strictのセッションCookieを使う。
HTTPSで公開するときは `EXAM_TRAINER_SECURE_COOKIES=true` も設定する。

シラバスは1行1項目で貼り付ける。ドットの番号が階層になる。

```
1 人工知能とは
1.1 人工知能の定義 | AI効果, チューリングテスト
2 機械学習の具体的手法
2.1 教師あり学習 | 線形回帰, SVM, 決定木
```

`|` 以降はキーワードで、生成時の検索語に使う。問題は項目のパス文字列で紐づくので、
シラバスを登録し直しても既存の問題は消えない。

### 教材を演習・弱点の選択欄へ登録する

教材一覧は固定のJSON、演習と弱点の右上の選択欄は学習DBの検定一覧です。
教材を追加した際は、不足する検定を次のコマンドで確認・登録します。

```bash
.venv/bin/python app/exam-trainer/scripts/import_learning_catalog.py
.venv/bin/python app/exam-trainer/scripts/import_learning_catalog.py --apply
```

確認だけの実行はDBを読み取り専用で開きます。`--apply`は設定済みDBの
`bank-before-catalog-*.sqlite`バックアップを所有者のみ読み取り可能な権限で作成し、
不足した検定・分野・問題を1トランザクションで追加します。既存の検定名があれば
その問題や履歴には触れず、再実行で重複しません。識別子が別の検定に使われている
場合は変更を中止します。サービス起動や公開ページからの自動取り込みはありません。

取り込んだ問題は演習に使えますが、取り込みは人による校閲を意味しません。
問題には元教材のSHA・問題ID・出典と来歴を記録し、演習と弱点に未校閲と表示します。
教材JSONの改訂を既存問題へ自動同期しません。取り込みを戻す場合は追加された検定IDを
対象にし、既存4検定とその履歴を維持してください。バックアップ全体の復元は、その後の
新しい解答履歴を失うため、通常の取り消し方法として使わないでください。
